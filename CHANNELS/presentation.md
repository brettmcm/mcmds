# Presentation Channel

> Optional production reference. This file does not define a separate design language. Start with `../DESIGN.md`; use this only for slide-production details.

Use this channel for decks, pitch presentations, strategy presentations, slide reports, keynote-style narratives, and leave-behind slide documents.

Use this file after `DESIGN.md` when the task needs detailed slide-production guidance.

## Presentation Mindset

Slides need rhythm. Each slide should have one job, and the sequence should control pace. The MCM presentation style should feel editorial and precise without becoming sparse to the point of being unhelpful.

Decide whether the deck is:

- Speaker-led: fewer words, stronger visual turns, more pacing.
- Leave-behind: more context, clearer captions, tighter information hierarchy.
- Hybrid: strong slide headlines with enough support to survive without narration.

## Slide Hierarchy

Use large display type for section turns, thesis slides, and key statements. Use restrained subheads for repeated slide titles. Use compact metadata for dates, sources, phase labels, and page numbers.

Large slide headlines may use tight negative tracking. Body, chart labels, source notes, and captions should use normal tracking.

## Layout

Use a consistent slide field and alignment system. Do not re-center every slide independently. Reuse a small number of layouts:

- Title / thesis
- Image-led statement
- Two-column argument
- Evidence / artifact
- Chart or table
- Section divider
- Closing / next step

Break the grid for section turns, strong images, or a major proof point. Keep operational slides calmer and more systematic.

## Visual Density

Speaker-led slides can be sparse. Leave-behind slides need more explanation, but should still feel edited.

If a slide has too much information:

1. Split it into multiple slides.
2. Promote the main claim.
3. Move detail into notes, appendix, or a secondary caption.
4. Simplify the visual system before shrinking type.

## Charts and Data

Use charts only when they add understanding. Clean tables are often better than decorative chart widgets.

For data-heavy slides:

- Lead with the takeaway.
- Use quiet labels and thin rules.
- Use orange only to call out the most important point, and only through type, data, imagery, or a compact non-linear mark. Never use an orange bar, rule, stripe, rail, divider, underline, or edge strip.
- Keep source notes present but subdued.

## Imagery

Image-led slides should show the subject, artifact, product state, place, person, or material. Avoid atmospheric filler when the audience needs evidence.

Use full-bleed or large-format imagery when the image is the point. Use smaller framed imagery when it is evidence inside an argument.

## Presentation Verification

Before finishing, check:

- Each slide has one clear job.
- The first read is obvious within a few seconds.
- Type is legible at presentation size.
- The deck has rhythm across title, argument, evidence, and transition slides.
- Speaker-led and leave-behind needs are not mixed accidentally.
